# Demo data: synthetic, not real

`demo-transactions.csv` and `demo-items.csv` are generated by `regulars/demo.py` for a
fictional venue, **Demo Wine Bar**. No real business, person, card or Square account is
involved. IDs start with `DEMO`, staff are "Demo Staff A–D", and URLs use the reserved
`.invalid` domain.

- 6 weeks (29 Sep to 8 Nov 2026), closed Mondays, ~3,300 transactions and ~7,300 item lines.
- Fri/Sat evenings peak; Melbourne Cup Tuesday (3 Nov) is busier; Tuesdays have an
  "Industry Night" discount; Wed to Fri 3 to 5pm has "Happy Hour".
- Includes full refunds (separate `Refund` rows plus negative item lines), partial refunds
  (in the `Partial Refunds` column), discounts, cash and gift-card tenders, an item name
  with a comma, one with embedded quotes, and non-ASCII text.
- **Customer names/IDs and note fields are planted on purpose** (`Demo Customer 12`,
  `DEMOCUST0012`, ...). They exist so the tests can prove the loader never stores them.

The column **names** follow the reference header rows in `regulars/schema.py`. The value
**formats and semantics** (money as `$12.50`, GST-inclusive prices, refund representation,
IANA time zone, ISO dates, a 1.9% illustrative card fee) are assumptions, not a description
of real Square output.

Regenerate (output is byte-for-byte deterministic, and a test fails if these files drift):

```bash
python -m regulars demo --out demo
```
